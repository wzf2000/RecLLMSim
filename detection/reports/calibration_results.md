# Post-hoc 校准结果（Option C）

## 动机

来自 `reports/anchor_and_diagnostics.md` 的诊断结论：
- **GPT-4o-mini**：预测分布塌缩到 4 分（pred 59.5% vs gold 37.8%），整体均值偏差小（-0.05），但类别边缘严重错配。
- **Qwen3-8B**：系统性低估（整体偏差 -0.20，平均绝对用户偏差 0.30），相对排序 OK（Pearson 0.30 左右）。

两者共同问题 → **模型的相对排序能力尚可，但绝对刻度偏离用户真实评分风格**。
最便宜的修复是：不改 prompt、不改推理，只按用户的**历史分数分布**（来自 memory cache 中的 `score_distribution` / `avg_satisfaction_score`）在 JSONL 上做 per-block 重映射。

## 实现

代码：`detection/eval/calibrate.py`，脚本：`detection/scripts/calibrate.sh`。

按 `(user, target_task, model)` 分块，每块做以下操作之一：

- **`identity`**  不改（sanity check）。
- **`mean_shift` (MS)**  平移使块内 `pred_mean ≈ hist_mean`，再 clip 到 [1,5] 并四舍五入。
- **`cdf`**  块内按 `pred_score` 升序排名（turn_idx 做稳定 tiebreak），按分位 `q=(rank+0.5)/n` 查询历史累计分布的逆函数，得到整数分。

降级策略：若历史 `n_history_turns < 5` 或块内样本 < 2，退化为 identity（本次 356 块中只有 1 块命中，覆盖率 99.7%）。

> ⚠ 注意：测试集的 `target_task` 在训练集（source_tasks）之外，即跨任务迁移——
> 前提是【用户评分风格】在任务间一致；该前提在数据上大体成立，见下面的增益。

## 分布层面的变化（节选，详见 `calibration_confusion.md`）

### GPT-4o-mini none_v2 —— 4 分塌缩被显著打开

| 分数 | gold % | 原 pred % | +MS pred % | +CDF pred % |
|---|---:|---:|---:|---:|
| 1 | 1.9%  | 0.5%  | 0.3%  | 1.7%  |
| 2 | 3.9%  | 1.5%  | 1.7%  | 3.0%  |
| 3 | 11.3% | 9.4%  | 10.2% | 11.5% |
| 4 | 37.8% | **59.5%** | 54.7% | **38.7%** |
| 5 | 45.1% | 29.2% | 33.1% | **45.1%** |

- **CDF 把边缘分布几乎完美对齐到 gold**（每档差距 <1%），系统性偏差从 -0.048 降到 +0.007。
- MS 只对均值，仍然高度集中在 4；但 MAE 更低，因为 gold 主要就在 4-5 档，集中到 4 已经不坏。

### Qwen3-8B none —— 低估被整体抬升

| 分数 | gold % | 原 pred % | +MS pred % | +CDF pred % |
|---|---:|---:|---:|---:|
| 1 | 1.9%  | 4.0%  | 3.8%  | 1.9%  |
| 2 | 3.9%  | 2.6%  | 1.9%  | 3.0%  |
| 3 | 11.3% | 20.1% | 15.5% | 10.3% |

- Qwen 的"相对排序好、绝对刻度差"假设 **被强支持**：仅做刻度对齐就能把 MAE 从 0.71 降到 0.63。

## 观察与建议

1. **CDF vs MS 的取舍**
   - **想要最低 MAE / RMSE** → 选 `mean_shift`（除 Qwen oracle 外各场景下 MAE 最优）。
   - **想要最强相关性 / 最准分布 / 最低用户偏差** → 选 `cdf`（Spearman、QWK、|bias| 几乎全线最好）。
   - MAE 和 Pearson 之间的取舍：MS 只改均值，预测依然倾向"集中在一两档"，所以每条绝对误差小；CDF 强制匹配整条分布，拓宽了预测范围，边际档上的 1-2 分差距会小幅抬高 MAE，但换来显著更准的分布与排序。

2. **哪个 backbone 从校准中获益最多**
   - **Qwen3-8B 收益极大**（MAE −10%+，Pearson +20%+，QWK +27%+）——验证了它的问题主要是绝对刻度。
   - GPT-4o-mini 收益中等（MAE −2%/+2%，Pearson +5%）——因为它的均值本来就接近 gold，主要问题是"分布坍缩到 4"，这对 MAE 影响小但对分布指标影响大，所以 CDF 在它上面对分布/相关性有大幅改善。

3. **PU / WC 指标下降**
   - per-user aggregation 指标（PUP / WCP）对校准都略有下降（~-0.02 到 -0.05）。
   - 原因：mean_shift / CDF 都会引入 clip+round，让原本接近（如 3.9 vs 4.1）的预测坍到同一个整数，破坏了块内的细粒度排序。
   - 若要同时保 PU 指标，可在最终输出前保留**连续值**（不 round），这对下游使用差异化的任务更友好——但目前 gold 本身是整数、其他指标也按整数计算，所以先保持现状。

4. **与 v2 oracle 对比**
   - GPT: oracle_v2 +MS 是目前 **MAE 最低**（0.6339）的 GPT 配置。
   - Qwen: oracle +CDF 的 Pearson (0.3572) 和 Spearman (0.3710) 是目前 Qwen 最好的配置，但 MAE 不是最优。
   - 结论：**memory v2 的 oracle 更新 + CDF 校准可以叠加使用**（都改善，不冲突）；也就是说之前 v2 的效果被绝对刻度问题掩盖了一部分。

## 成本与局限

- **成本**：零 API 调用、单次处理 6474 条 < 1s。几乎免费。
- **依赖**：要求 memory cache 中有该 (user, task, model) 的 `score_distribution` 和足够历史 turns（默认 ≥5）。本次 356 块中 355 块满足。
- **跨任务假设**：用户在训练集任务上的评分风格被假定能迁移到测试集 target_task。从 Qwen 的大幅提升看，这一假设在本数据集上成立；但在其他数据集上应先验证（e.g. 计算训练 vs 测试集上用户均值相关系数）。
- **对于罕见分数（1, 2）**：历史分布中如果某用户从未给过 1 分，CDF 也不会预测 1 分。这其实是合理偏差——但会让极端错判（真实 1、预测 5）无法被完全修复（初始表里 GPT 把真实 1 分的 45% 判给了 4，这种"硬错"校准也无能为力）。

## 下一步建议

1. **立即可做**：把最好的配置写回 `personalized_satisfaction_results.md` 的主表。
   - GPT 推荐：`oracle_v2 +MS`（MAE 0.634）或 `oracle_v2 +CDF`（相关性最强）
   - Qwen 推荐：`oracle +CDF`（Pearson 0.357、Spearman 0.371，MAE 0.636）
2. 再评估 anchor + CDF 的叠加效果（只需对已有 anchor JSONL 跑 `calibrate.sh`）——预计 CDF 能进一步打平 anchor 版本里那个"MAE 小幅下降、Pearson 小幅下降"的 tradeoff，因为 anchor 提升的是局部判别，而 CDF 修的是全局刻度，两者正交。
3. 如果未来做 rubric 迭代，应优先收集**用户评分分布变化**的反馈而不是"绝对分数错误"的反馈，因为绝对分数错误大多数可以被后处理修掉。
