# Memory v2 设计文档

> 本文档记录 v1→v2 的改进动机、具体设计决策及效果验证。

---

## 1. v1 的三个根本问题

| 问题 | 表现 | 根因 |
|------|------|------|
| 内容同质化 | 所有用户的记忆几乎一样，泛化描述无区分度 | Schema 字段设计为"模式列表"，LLM 倾向于输出通用描述 |
| 评估时未被引用 | 仅 33% 的 analysis 提及记忆 | Memory 以"参考以下模式"方式呈现，LLM 不知如何使用 |
| 更新无效 | Oracle 更新与 none 几乎相同（Δ < 0.002） | 记忆已饱和；update prompt 过于保守；内容质量差导致更新无意义 |

---

## 2. v2 Schema 改动

### 移除的字段

```python
# v1（移除）
high_satisfaction_patterns: list[str]   # 泛化满意模式
dissatisfaction_patterns: list[str]     # 泛化不满意模式
notable_user_characteristics: list[str] # 泛化用户特征
```

### 新增的字段

```python
# v2（新增）
scoring_style: str
# 评分风格 + 校准说明，例：
# "偏严格：平均分 3.8，5 分门槛很高，需回复完全命中且格式完美"

four_vs_five_distinction: str
# 4分→5分的具体门槛，必须引用实际历史轮次的差异

three_vs_four_distinction: str
# 3分→4分的具体门槛，必须指出导致跌至 3 分的缺陷类型

user_specific_requirements: list[str]
# 该用户独有要求，禁止泛化描述
# 好的示例："要求提供可购买的具体品牌和价格区间"
# 禁止示例："回复要详细"
```

### 缓存版本控制

`UserMemory` 新增 `memory_version: str = "v2"`，加载缓存时检查版本，版本不匹配自动重建，避免 v1 缓存污染 v2 实验。

## 3. v2 Prompt 改动

### Memory Building Prompt

在顺序展示历史 sessions 之后，新增**"按分数分组的对比证据"**区块：

```
═══ 按分数分组的对比证据（重点参考）═══

▸ 5 分轮次（共 N 轮，展示 3 条）：
  [1] 任务：旅行规划
      用户提问：...
      助手回复：...

▸ 4 分轮次（共 N 轮，展示 3 条）：
  ...

▸ 3 分轮次（共 N 轮，展示 3 条）：
  ...
```

**效果**：LLM 被迫直接对比相邻分数的差异，而非自由发挥泛化总结。

分析任务指令中明确要求：
- "须基于历史数据中实际出现的 4 分和 5 分轮次的差异"（禁止凭空编造）
- "禁止使用对所有用户都成立的泛化描述"

### Turn Evaluation Prompt（rubric 式）

v1 prompt 风格：
```
请参考以下用户记忆模式进行评分：...（附记忆内容）
```

v2 prompt 风格（3 步 rubric）：
```
【评分步骤】请严格按以下顺序推理：
Step 1: 对照【3分以下→4分的门槛】判断此回复是否达到 4 分基线
Step 2: 若达到 4 分，再对照【4分→5分的门槛】判断是否满足 5 分条件
Step 3: 若未达到 4 分，根据缺陷严重程度（参考用户特定要求）决定给 1/2/3 分
```

v2 prompt 将记忆转化为**可执行的逐步判断流程**，而非"参考信息"，强制模型按步骤使用记忆内容。

### Memory Update Prompt（保守更新）

v2 新增明确的保守性指令，区分 oracle 和非 oracle 情况：
- Oracle 模式："本次提供了真实标签，可作为可靠证据更新记忆"
- 非 Oracle 模式："本次仅有模型预测分数（可能有误），**请谨慎参考，不要因预测误差大幅修改已有记忆**"

## 4. v2 效果验证（GPT-4o-mini）

| 指标 | v1 none | v2 none | 提升 |
|------|--------:|--------:|-----:|
| MAE | 0.7722 | 0.6517 | −0.1205 (−15.6%) |
| RMSE | 1.0938 | 0.9591 | −0.1347 (−12.3%) |
| Pearson | 0.2227 | 0.3146 | +0.0919 (+41.3%) |
| Spearman | 0.1993 | 0.2911 | +0.0918 (+46.1%) |
| Kappa | 0.2215 | 0.3002 | +0.0787 (+35.5%) |

v2 还修复了 oracle 更新无效的问题：
- v1: oracle (0.2196) ≈ none (0.2227)，差异 < 0.003
- v2: oracle (0.3330) > none (0.3146)，差异 +0.018，oracle 更新有实质意义

## 5. 参数配置

`lib/memory.py` 中的截断常量（兼顾 prompt 长度与信息量）：

```python
_MAX_REPLY_CHARS = 200       # 单条 assistant 回复截断字符数
_MAX_SESSIONS_PROMPT = 8     # 放入 prompt 的最大历史 session 数
_MAX_EXAMPLES_PER_SCORE = 3  # 对比证据区每分数等级展示的最大轮次数
```

> 注：原始值为 250 / 12 / 4，为兼容本地模型（Qwen3-8B，max_model_len=16384）而收紧。
